01構想と結論

Mirai Web CADは、AutoCADやARES Standardの操作をそのままWebへ移すだけの製品ではない。自然言語、既存図面、設計資料、座標、施工条件からAI Agentが作図案・数量・工程・比較案を生成し、人が技術判断、修正指示、承認を行う「AI-first型 土木施工図プラットフォーム」である。

基礎には、AutoCAD／ARES Standardの主要な2D機能を実務利用範囲で80～90％カバーする「Mirai 2D CAD Core」を置きます。ただし、価値の中心は機能数の追随ではなく、作図前後の業務をまとめて省力化することです。

「80～90％」の意味

製品全機能の個数ではなく、社内で実際に使われる2D作図操作・図面形式・印刷・修正・照査の利用頻度と業務時間を基準にカバー率を測ります。高度な3D、レンダリング、業界外の特殊機能、希少なアドオン互換は対象外です。

判定基準：代表的な施工図業務の80～90％が、他CADへの往復なしで完成・検査・出力できること。単にメニューが存在するだけでなく、精度・操作速度・互換性・印刷品質まで満たすことを条件とします。

対象組織の前提：土木・建設業、従業員約600名、IT・DX部門7名、公共工事約80％・民間工事約20％。少人数のIT・DX部門でも継続運用できることを重視します。

06AI Agent＋Skillsの設計

Agentは作図依頼を分解・実行し、Skillは会社が承認した作図手順、レイヤー、図枠、命名、チェック項目を強制します。AIは座標値を曖昧に描画せず、最終的な図形生成・編集はMirai 2D CAD Coreの厳密なコマンドで実行します。

Supervisor Agent

依頼を分解し、必要なSkillと専門Agentを選択。未確定条件があれば処理を止めて質問。

Drawing Agents

作図、編集、寸法、レイヤー整理、ブロック化、数量拾い、レイアウト・出力を担当。

Verification Agent

作成担当とは独立して、入力・図面・数量・計算・版の矛盾を再検査。

07正確性を支える7層

1. 入力検証 — 必須項目、単位、座標系、異常値、資料間矛盾、基準年度を検査。
2. 承認済み専門Skill — 工法別の手順と中止条件を固定し、自由解釈を抑制。
3. 決定論的CAD Core — 座標、幾何、変換、寸法、数量は同じ入力から同じ結果を返すエンジンが担当。
4. ルール検査 — 離隔、数量一致、部材数、尺度、基準年度などをプログラムで厳密判定。
5. 独立検証 — 作成Agentと検証Agentを分離し、同じAgentによる自己採点を避ける。
6. 既知事例との比較 — 承認図、標準計算例、既存ソフト、実績、不具合事例との差を検知。
7. 人による承認 — 入力、根拠、警告、差分を見て技術者・権限者が正式採用を判断。
AIが保証できないもの：誤った元資料、未記載の現場条件、未知の特殊構造、解釈が分かれる基準、施工時に変動する地盤・水位、古いSkill。したがって、Skill自体にも版管理・レビュー・承認・失効管理が必要です。

11推奨する正式方針

Mirai Web CADは、基本的な2D CAD機能を徹底的に磨き、AutoCAD／ARES Standardで日常的に行う2D作図・編集・注釈・レイアウト・印刷・DWG/DXF/PDF交換業務の80～90％を、Webブラウザ上で代替することを第一目標とする。AI Agent＋専門Skillsは、CAD Coreを置き換えるものではなく、作図・修正・標準化・数量拾い・図面検査を高速化する中核支援機能として実装する。

開発判断

項目判断理由
AutoCAD／ARESの完全コピー行わない開発負荷が大きく、独自価値になりにくい
主要2D機能80～90％カバー目指す現場が既存CADへ戻らずに済む編集基盤が必要
AIによる初稿・再作図中核にする作図そのものを減らす最大の差別化要因
Agent＋Skills中核にする会社標準と専門手順を再利用可能な知識資産にできる
3D・BIM/CIM・構造計算対象外2D CADの完成度、速度、互換性へ開発資源を集中する
DWG/DXF往復互換性重点投資既存CAD利用者・協力会社との実務交換に不可欠
コマンド・ショートカット互換重視する既存利用者の学習コストと操作速度低下を抑える
最初の実証テーマ：「仮設構台または施工ヤード図」を一つ選び、既存図面10～30件を匿名化・クレンジングして標準パターンを抽出。AI初稿、数量、整合検査、修正時間を現行作業と比較します。小さく始めても、設計思想は大きく持てます。
