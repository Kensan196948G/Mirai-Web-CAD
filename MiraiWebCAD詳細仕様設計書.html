01論理アーキテクチャ

CAD CoreはAIから独立し、同じコマンド入力に対して同じ図形結果を返す。AgentはCAD Core APIを利用する一利用者であり、図面データを直接更新しない。
層責務禁止事項
Presentationキャンバス、パネル、コマンドライン、レビューUI図形真値の保持
Applicationコマンド実行、選択、Undo、保存、権限、Workflow幾何計算の重複
CAD Core図形、幾何、交差、変換、スナップ、測定、空間索引LLM呼出し
File EngineDWG/DXF/PDF変換、差異検査、Font・線種Mapping警告の黙殺
Agentic計画、Skill選択、Tool Call生成、説明、検証DB・図面の直接書換え
Persistence図面、版、Event、添付、監査、Skill、Job保存承認版の上書き

推奨実装境界

  • Client：TypeScript、WebGL2/WebGPU対応Renderer、Web Worker。
  • CAD Core：TypeScript＋WASM適用可能な純粋Geometry Module。
  • API：REST＋WebSocket。変換・Agent処理は非同期Job。
  • DB：PostgreSQL互換。図面原本・PDFはObject Storage。
  • AI Providerは抽象化し、Model変更がCAD Coreへ波及しない構成。

03CAD Core仕様

座標・精度

項目仕様
内部座標IEEE 754倍精度。World座標とView座標を分離
単位mm、cm、m、inch、ft。図面単位と表示単位を分離
角度内部radian、表示degree。0方向と回転方向を設定可能
許容差図面範囲に応じたepsilonを一元管理
大座標描画時にLocal OriginへShiftしGPU単精度誤差を抑制

図形型

Line、Ray、XLine、Polyline、Circle、Arc、Ellipse、Spline、Point、Text、MText、Dimension、Leader、Hatch、BlockRef、ImageRef、Viewport。

Rendering

  • Model座標から画面座標への変換はCameraが一元管理。
  • 表示範囲内のみ描画し、Layer状態・尺度・線種をBatch処理。
  • 選択・Snap用ID Bufferまたは空間索引を描画と分離。
  • 線幅・破線・Hatch・文字は画面簡略表示と印刷表現を切替。

Command Interface

interface CadCommand {
  id: string;
  execute(ctx: CommandContext, args: CommandArgs): CommandResult;
  undo(ctx: CommandContext): void;
  redo(ctx: CommandContext): void;
  preview?(ctx: CommandContext, args: PartialArgs): PreviewGeometry;
  serialize(): CommandEvent;
}

一回のUser操作または一回のAI提案適用をTransactionとしてまとめ、全体を原子的にUndo可能とする。

08DWG／DXF／PDF処理

1. 原本を不変保存しHash・形式・版を記録
2. Virus／形式検査、Size・暗号化・破損を判定
3. 中間表現へ変換し、未対応要素と代替処理を記録
4. 内部図形ModelへMappingしPreview表示
5. 出力後に再読込し往復差異を比較
差異区分検査
Geometry要素数、型、端点、中心、半径、長さ、面積、BBox
StyleLayer、色、線種、線幅、透明度
Annotation文字列、位置、Font、文字高、寸法値・Style
StructureBlock、属性、Xref、Layout、Viewport

差異はCritical／Major／Minor／Infoへ分類し、Critical時は正式出力を警告または停止する。

09Agentic AI詳細設計

実行状態

RECEIVED → ANALYZING → NEEDS_INPUT → PLANNED → PREVIEWED
→ USER_APPROVED → EXECUTING → VERIFYING → COMPLETED
                  ↘ REJECTED / FAILED / ROLLED_BACK

各状態のGate

状態必須条件次状態
ANALYZING権限、図面版、Scope、入力を確認NEEDS_INPUT / PLANNED
PLANNEDSkill、Tool、対象図形、変更上限、検証方法を確定PREVIEWED
PREVIEWED追加・変更・削除・警告・根拠を可視化USER_APPROVED / REJECTED
EXECUTINGServer側でTool Callを再認可・Schema検証VERIFYING / FAILED
VERIFYING独立Agent＋Rule EngineがPostconditionを検査COMPLETED / ROLLED_BACK

Structured Tool Call例

{
  "tool": "cad.command.batch",
  "drawingVersion": 42,
  "transactionId": "agt_01...",
  "skill": {"id":"civil-drawing-standard","version":"1.2.0"},
  "commands": [
    {"name":"LAYER_SET_CURRENT","args":{"name":"仮設"}},
    {"name":"PLINE","args":{"points":[[0,0],[8000,0],[8000,6000],[0,6000]],"closed":true}},
    {"name":"OFFSET","args":{"entity":"preview:e1","distance":500}}
  ],
  "postconditions": ["no_locked_layer_change","geometry_valid"]
}

Agent Guardrails

  • Read ToolとWrite Toolを分離し、既定はRead-only。
  • Writeは利用者のPreview承認後だけ短寿命Tokenで許可。
  • Tool、図形数、処理時間、Token、費用、再試行回数を上限管理。
  • 承認済み版、Lock Layer、権限外Project、未対応図形を変更禁止。
  • 図面内文字・添付文書を非信頼データとして隔離。
  • 同一失敗3回で停止し、無限Loopを禁止。
  • Agentが生成した説明よりCAD Core・Rule Engine結果を優先。

MemoryとContext

種類内容保持
Run Context現在依頼、選択図形、図面状態Run終了まで
Project Context図枠、Layer標準、利用TemplateProject期間
Approved KnowledgeActive Skill、承認図、標準部品版管理

会話履歴を無制限に図面判断へ利用せず、正式な根拠はSkill、Project設定、選択資料へ限定する。

Skill Eval指標

  • Task Success Rate、正しいSkill選択率、必須質問Recall。
  • Tool Call Schema合格率、禁止Tool呼出し率0％。
  • Geometry一致率、Layer／寸法／Plot Rule合格率。
  • 不要変更図形数、差戻し率、利用者修正時間。
  • 曖昧・悪性・Scope外入力の安全停止率。

11Agent Orchestration・検証

Supervisor：依頼と図面状態を読み取り、Task Graphを作成
Policy Engine：Role、Skill、Tool、変更上限を認可
Specialist Agents：互いに独立した構造化Proposalを作成
Composer：依存関係と競合を解消してPreview Transactionを構成
User Gate：追加・変更・削除を確認し、全体または部分承認
CAD Core：Transactionを原子的に実行
Verification Agent＋Rule Engine：Postconditionと差分を検査
CommitまたはRollback：版とAuditを確定

競合解決

  • 同一図形への複数提案は自動Mergeせず、優先理由と差分を表示。
  • Layer変更と図形変更は依存順を明示し、失敗時はTransaction全体をRollback。
  • Verification Agentは作成AgentのChain-of-Thoughtを参照せず、入力・結果・Ruleだけで評価。
  • Rule EngineのHard FailはAIの説明で上書きできない。

14保存・版・共同作業

  • Local操作は即時Command Queueへ入り短間隔でServer永続化。
  • 通信断時は暗号化Browser領域に保留し再接続時に版照合。
  • 同一図形の同時変更は自動上書きせずConflict表示。
  • 承認済み版はImmutable。編集開始時に派生Draft作成。
  • Auto Save、Manual Checkpoint、Formal Versionを区別。
  • Crash復旧時は最後のSnapshot＋Command Eventを再生。

主要不変条件

  • 保存→読込で図形の意味と座標が変わらない。
  • Command→UndoでBefore Hashへ戻り、RedoでAfter Hashへ戻る。
  • Lock Layerの図形は手動・Agentとも更新できない。
  • AI却下時に図面版・図形・履歴が変わらない。
  • 承認済み版を直接変更できない。
  • Revoked Skillを新規Agent Runで実行できない。

18配備・監視・運用

  • 開発、検証、Staging、本番を分離し、図面・Secretsを混在させない。
  • DB Migrationは後方互換を保ち、図面SchemaにVersion Migratorを用意。
  • Feature Flagで新Command、変換Engine、Agent、Skillを段階配信。
  • 監視：Web Vitals、FPS、Command Latency、保存失敗、変換差異、Agent成功率・時間・費用。
  • 重大障害時はAIのみ停止、変換のみ停止など機能単位で縮退運転。
  • Skill・AI Model変更時はGolden Evalを実行し、回帰時は自動Deploy停止。
実装順：CAD CoreとUndo/保存 → 基本Command・Snap → 注釈・Layer・Block → Layout・PDF → DWG/DXF → Agentic AI＋Skills → 性能・代替率実証。AIを先に作ってCADが後になる順番は採用しない。
